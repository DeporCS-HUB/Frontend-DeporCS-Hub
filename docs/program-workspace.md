# Compact program dashboard

The dashboard shows four KPIs (completed activities, recorded percentages, completed tasks, overdue tasks) and three native bar charts. Proker/UKOR percentage charts preserve unknown values as dashed tracks and an em dash rather than zero. Status distribution shows actual Completed, Active/Ongoing, Planning, Unspecified and Cancelled counts. Staff charts switch between assigned activity status, completed/assigned tasks and actual updates in 30 days. Status segments show counts rather than an invented average performance score; Staff without assigned tasks show an em dash.

Charts use native HTML/CSS, keyboard-accessible values and screen-reader labels. No chart dependency is added to the dashboard. Chart rows and labels are compact, Staff lists have a bounded scroll region at larger roster sizes, and layouts adapt to mobile. Values come from the existing cached dashboard RPC; its displayed activity list remains bounded by the API. Existing finance charts retain their separate lazy-loaded bundle.

Programs shows only name/category, PJ, status/percentage, next known date and actions. Descriptions, notes, full agenda, budget and dates remain available in Detail. On mobile, each table row becomes an action-accessible compact card. Task cards also open descriptions through Detail. Dialogs cap their viewport height and scroll internally, trap keyboard focus, close with Escape and restore focus to the triggering button.

Assigned Staff and BPH retain Update progres; BPH retains full editing and multiple account-linked PJ assignments. Date/budget/percentage values remain optional. No permissions, Auth, database records or API contracts changed in this UI iteration. Failed saves retain confirmed data; successful saves invalidate dashboard/list cache as before.

Verification: build/lint and 22 unit tests. The browser suite contains 17 mocked-API flows, including chart metric switching, unknown-vs-zero percentages, PJ editing/persistence, multiple PJs, bounded long descriptions and keyboard focus on mobile. Desktop/mobile visual QA uses a development data snapshot with mocked Auth/API routing. These checks do not certify a real hosted Auth login or cross-domain refresh cookies. No paid services or dependencies were added.
